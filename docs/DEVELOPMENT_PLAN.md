## 第一章 先认识 Andy：定位、功能与技术栈

### 1.1 先看一个真实场景

晚上 11 点，Wen 问 Andy：

> “明早怎么安排？我下午还要改简历。”

一个合格的 Andy 不应该只回一段“建议你早点睡”的文字，而应该：

1. 读取今天没做完的任务、明天的截止时间、已设置的提醒；
2. 知道 Wen 最近在准备软考/求职，不会排出“明早 6 点起来刷三套题”这种不现实的计划；
3. 从自己的笔记/文档里找到“简历修改”的上下文，而不是编一个通用建议；
4. 把“明早 8 点提醒交材料”真正写进任务/提醒；
5. 在写入前让 Wen 确认，做完后留下可回看的记录。

这就是 Andy 和通用聊天助手最本质的区别：**它不只需要“会回答”，还需要“知道你的上下文、能记住、能动手、并且动手前经过你同意”。**

### 1.2 一句话定位

**Andy 是一个本地优先、单用户的个人事务代理：以任务、提醒、记忆、知识为核心，桌面窗口为入口，MCP/浏览器/文件为手脚，语音为输入输出。**

拆开看：

- **本地优先**：数据库、记忆、日志、模型配置优先放在本机；能不把隐私数据传出去就不传。
- **单用户**：先服务 Wen 一个人，不急着做多用户、权限体系、云 SaaS。
- **个人事务代理**：核心场景是学习、求职、项目、生活安排，不是通用问答，也不是替代 IDE 的编程 Agent。
- **有手脚**：不只是聊天，能创建任务、设提醒、查知识、以后还能查网页/读文件。
- **有边界**：写入、执行、发消息、花钱这类动作必须确认；高风险任务要隔离。

### 1.3 Andy 要做的四件事

| 核心能力 | 具体表现 | 现在的基础 |
|---|---|---|
| **记得住** | 记住 Wen 的偏好、目标、项目、考试、重要事件；能区分“当时”和“现在” | SQLite + 语义事实 + 向量检索 |
| **管得清** | 任务、截止时间、提醒、今日概览、周复盘 | 三线看板 + 调度器 |
| **查得到** | 从个人文档、笔记、项目资料里找答案，并给出来源 | `rag.search_knowledge` + embedding |
| **做得成** | 调用工具完成任务；以后接浏览器/文件/桌面操作 | function calling + MCP stdio |

### 1.4 Andy 不做什么

- 不做“又一个 ChatGPT 客户端”：通用聊天、通用写作，用豆包/WorkBuddy 更合适。
- 不做通用编程 Agent：不替代 IDE、不自动改整个代码库；可以读项目、总结、提建议，但不把“自动写代码”作为主线。
- 不做 Skill 商店：通用技能是商品，Andy 的护城河是 Wen 的私人上下文和长期流程。
- 不做多用户云平台：现阶段没有收益，反而会拖慢可靠性。
- 不做无确认的自动操作：不自动发微信、不自动付款、不自动提交表单。

### 1.6 技术栈小白速查

| 名词 | 大白话 | 在 Andy 里干什么 | 为什么需要 |
|---|---|---|---|
| **Python** | 写程序的语言 | 全部后端、桌面、工具逻辑 | 生态全，开发快，适合个人项目 |
| **PyQt6** | 做 Windows 桌面窗口的工具 | 三线看板、对话区、按钮、弹窗 | 比 Web 套壳更轻，能直接操作本机 |
| **SQLite** | 一个存在本地文件里的数据库 | 任务、提醒、对话事件、事实、向量 | 不需要装数据库服务，拷走文件就能备份 |
| **智谱 GLM / OpenAI SDK** | 调用大模型的“电话线” | 生成回复、决定调用哪个工具 | 模型负责“理解”，代码负责“执行” |
| **function calling** | 让模型按固定格式“点菜” | 模型输出 `task_create(...)` 这样的工具请求 | 把“会说”变成“会做” |
| **MCP** | 一种让外部程序提供工具的标准接口 | 接 demo server、以后的浏览器/文件服务 | 加能力不用改主程序 |
| **Embedding** | 把文字变成一串数字，用数学找“意思相近” | 记忆检索、知识库检索 | 解决“换个说法也能找到” |
| **Vosk** | 离线语音识别工具 | 把麦克风里的中文转成文字 | 不联网、不把录音传云端 |
| **sounddevice** | 读取麦克风的工具 | 采集 16kHz 单声道音频 | 比 PyAudio 更容易装 |
| **edge-tts** | 在线语音合成 | 把整段回复读出来 | 音色自然，中文支持好 |
| **pyttsx3 / SAPI** | Windows 自带语音 | edge-tts 失败时离线兜底 | 断网也能出声 |
| **PyInstaller** | 把 Python 项目打成 exe | 生成可分发的桌面程序 | 用户不用装 Python |
| **pytest** | 自动跑测试的工具 | 防止改 A 弄坏 B | 个人项目也必须有回归网 |

如果只想先记住一件事，可以这样串：**PyQt6 是门面，Python 是骨架，SQLite 是笔记本，GLM 是顾问，function calling 是手，MCP 是外挂插座，Vosk 是耳朵，edge-tts 是嘴。** 门面负责让你看见和点击，骨架把各部分连起来，笔记本负责记住，顾问负责理解，手负责真的去改任务/设提醒，插座负责接外部工具，耳朵和嘴负责语音输入输出。

### 1.7 一次对话的数据流

以“明天下午三点提醒我交周报”为例：

1. 桌面层把文字交给 Agent 运行时；
2. 运行时把最近对话、相关记忆、任务概览组装成上下文；
3. 模型判断要调用 `reminder_create`，并给出时间、内容；
4. 运行时检查权限：这是写入动作，需要确认；
5. 用户在窗口里点“允许”；
6. 工具写入 SQLite，调度器开始盯这个提醒；
7. 模型根据工具结果生成回复；
8. 桌面层流式显示文字；回复结束后，整段交给 TTS 朗读；
9. 这一轮的用户输入、工具调用、确认、结果、耗时写入轨迹日志。

## 第二章 本轮已完成的语音改造

### 2.1 语音输入（ASR）

**目标**：说完话，文字进入输入框，不用键盘。

实现：

- 新增 `core/asr.py`：Vosk 离线识别 + `sounddevice` 麦克风采集；
- 新增 `ASRWorker`：录音/识别放到子线程，不卡窗口；
- 输入框旁新增“🎤 语音输入”按钮：点一下开始，再点一下停止；
- 边说边显示临时结果；停止后把最终文本填入输入框，按回车发送；
- 缺模型、缺依赖、没麦克风时给出明确提示，不让程序崩。

> 说明：用户原话中的“AST”按 **ASR（Automatic Speech Recognition，自动语音识别）** 实现。

### 2.2 语音播报（TTS）

**目标**：不再边流式边一句一句读，改为“回复完整后，整段合成一次”。

实现：

- 桌面层 `_on_chunk()` 不再触发 TTS；
- `_on_done()` 拿到完整 `reply` 后调用一次 `speaker.speak(reply)`；
- `Speaker._play_edge()` 不再按句拆分，整段生成一个音频文件；
- 保留 `TTS_MAX_CHARS` 上限，避免超长回答念太久；
- 相关单测从“分句播放”改为“整段只合成一次”。

### 2.3 本轮验收结果

- `pytest tests -q`：**95 passed**（ASR 7 项，语音 15 项，基本问答 16 项，MCP 7 项，运行时事件 4 项）；
- `python main.py --selftest`：**11 项健康检查全 OK**，截图 `logs/selftest_window.png`，窗口可见“🎤 语音输入”“朗读”“语言/音色”；
- ASR 真实模型：`vosk-model-small-cn-0.22.zip` 完整大小 **43,898,754 字节**，解压后识别中文 TTS 样本，输出“你好我是安迪”；
- TTS 整段合成：中文回复生成 **1 个 mp3**，大小 32,256 字节，时长 **5.376 秒**；
- 未覆盖：真人麦克风端到端、嘈杂环境识别率、长回复整段朗读的听感；这三项要在 Phase 0 的窗口级验收里补。

## 第四章 打包后的扩展架构

### 4.1 核心原则

**exe 只装内核，能力放外面。**

```
Andy.exe
resources/              # 内置图标、默认提示词
capabilities/
  mcp/servers.json      # MCP 服务清单
  skills/               # Markdown 技能包
  recipes/              # YAML 个人配方
  plugins/              # 独立进程插件（可选）
user_data/              # 数据库、记忆、日志、知识库
```

### 4.2 四种扩展插槽

| 类型 | 放哪里 | 要重新打包吗 | 适合 |
|---|---|---|---|
| MCP 服务 | `capabilities/mcp/servers.json` | 不需要 | 新工具、浏览器、文件、数据库 |
| 技能包 | `capabilities/skills/<name>/SKILL.md` | 不需要 | 提示词、流程、个人经验 |
| 配方 | `capabilities/recipes/<name>.yaml` | 不需要 | 早间简报、周复盘、考试冲刺 |
| 原生插件 | `capabilities/plugins/<name>/` | 不需要 | 必须写新代码，但建议独立进程 |

### 4.3 打包前必须改的路径

当前 `config.py`：

```python
BASE_DIR = os.path.dirname(os.path.abspath(__file__))
```

打包后不可靠：PyInstaller onefile 运行时会解压到临时目录，`__file__` 指向那里，不是 exe 所在目录。

建议改为：

```python
APP_DIR = Path(sys.executable).parent if getattr(sys, "frozen", False) else Path(__file__).parent
USER_DATA_DIR = Path(os.getenv("ANDY_HOME", Path.home() / "AppData/Local/Andy"))
```

原则：

- 默认资源从 `APP_DIR/resources` 读；
- 数据库、日志、`mcp_servers.json`、`capabilities/` 从 `USER_DATA_DIR` 读；
- 升级 exe 不碰用户数据；
- 打包用 `--onedir`，比 `--onefile` 更稳、启动更快、路径更好找。

### 4.4 扩展的安全边界

- 插件是代码，默认不信任；安装时显示权限，用户确认。
- 插件不直连 SQLite，通过宿主 API 读写，避免 schema 变更把插件弄坏。
- 不在运行时自动 `pip install`；插件依赖自己带，或做成独立 exe。
- 不自动从网络安装插件；只支持本地文件夹放入 + 重启。
- 插件声明 `api_version`，不兼容时禁用该项，不让整个程序崩。

## 第五章 评测与验收

### 5.1 测试分层

| 层级 | 内容 | 工具 |
|---|---|---|
| 单元测试 | 记忆、任务、语音、ASR 文本处理、工具参数校验 | pytest |

### 5.2 关键指标

- 任务完成率：固定 30 个场景，成功/部分成功/失败；
- 工具选对率：该调工具时调对，不该调时不乱调；
- 记忆召回率：问旧事能找到，问现在不被旧事实干扰；
- 引用准确率：知识回答的来源真的支持结论；
- 首字延迟、整段 TTS 延迟、ASR 识别耗时；
- 误操作率：未确认的写入/执行次数必须为 0。

## 第六章 风险与边界

| 风险 | 影响 | 应对 |
|---|---|---|
| ASR 模型体积大 | 打包变大、首次启动慢 | 模型外置，首次启动下载/导入；不塞进 exe |
| 麦克风环境差 | 识别率低 | 显示临时结果；支持重录；保留键盘输入 |
| TTS 整段合成延迟 | 长回复等待久 | 保留字数上限；长回复可只读摘要 |
| 插件任意代码 | 安全风险 | 权限声明 + 确认 + 独立进程 + 不自动安装 |
| 模型乱调工具 | 误写/误操作 | 权限分级 + 参数校验 + 确认 + 审计 |
| 打包路径错误 | 配置/数据找不到 | `APP_DIR` / `USER_DATA_DIR` 解耦，干净机器烟测 |
