# Andy（Baymax_pro） 产品需求文档（PRD）

> 版本：v2.1（定位调整版）
> 日期：2026-11-25
> 上一版：v2.0（健康陪伴宠物，2026-11-03）
> 变更摘要：核心定位由"健康陪伴宠物"调整为"学习/工作/生活三线个人管理助理"；健康陪伴降级为保留模块；新增任务管理、指令编排执行、MCP 扩展三条主线

---

## 1. 产品定位

**Andy是一个常驻 Windows 桌面的个人管理助理——接收你的指令，把它拆成可执行步骤并调用工具完成；维护你的学习、工作、生活三条线的任务进度；在正确的时间主动提醒你。**

一句话拆解：
- **是什么**：桌面常驻 AI 助理 + 三线任务管理器
- **给谁用**：本人（大三计算机学生，学习/求职/生活多线并行）
- **解决什么**：任务散在脑子里和多个 App 里、提醒靠记性、跨工具操作要手动切窗口

### 1.1 定位调整的取舍说明

| 维度 | v2.0 旧定位 | v2.1 新定位 | 取舍理由 |
|---|---|---|---|
| 核心价值 | 情感陪伴 + 健康科普 | 任务编排 + 主动提醒 + 进度管理 | 陪伴"可感知但难量化"，管理"每天真实发生且能验收" |
| 可复用性 | 只服务自己，场景窄 | 学习/工作/生活都能用，家人也能用 | 面试时能讲清架构与业务价值 |
| 健康陪伴 | 核心 P0 | 保留为独立模块（S5） | V1 已有能力不浪费，作为"生活"域的一个子能力 |
| 风险 | 健康建议有边界风险（不能诊断） | 任务管理风险低，可放心主力做 | 避免产品一开始就踩医疗红线 |

> 结论：新定位不否定旧方向，而是把"健康"收进"生活"域，让主链更清晰、可交付性更强。

## 3. 功能清单

### 3.1 P0 核心（Must，本期必须做）

| # | 功能 | 描述 | 验收标准（可测试） |
|---|---|---|---|
| M1 | **简约桌面窗口** | 三线任务看板 + 任务编辑 + 提醒设置 + 对话输入区 | 启动即可见；可增删改任务；窗口置顶可拖动；关闭后进程退出干净 |
| M2 | **任务管理（三线）** | study/work/life 三域任务：标题、状态、优先级、截止、进度、子任务 | 新建后重启仍存在；改状态/进度立即生效；子任务挂在父任务下 |
| M3 | **实时提醒** | 一次性（某日某时）、每日、每周、cron 规则 | 到点触发弹窗；重启后规则仍在；关机错过在下次启动补发并标注"错过 N 次" |
| M4 | **指令拆解 + 工具执行** | 一句话 → 模型判断是否用工具 → 执行 → 回报结果 | "明天 9 点提醒我交作业"能建出提醒；工具失败有明确错误而非假装成功 |
| M5 | **记忆层** | 三层记忆 + 上下文组装，详见 `docs/MEMORY_DESIGN.md` | "我周三上午 9 点软考"，十轮后问"这周有什么大事"仍能答出 |
| M6 | **今日概览** | 汇总今日待办、逾期、近期截止、今日提醒 | 每日首次对话自动带出概览；数字与实际任务表一致 |
| M7 | **全链路验证** | 按验收点逐项跑通 | 检查表 100% 通过，无已知阻塞缺陷 |

### 3.2 P1 次要（Should，第二阶段）

| # | 功能 | 描述 | 验收标准 |
|---|---|---|---|
| S1 | **MCP 客户端** | 支持 stdio 与 HTTP/SSE 两种传输，动态加载外部工具 | 能列出远端工具、调用成功、失败可诊断 |
| S2 | **对接自建 FastAPI 服务** | 把已有 FastAPI 项目的能力接入为Andy的工具 | Andy能读/写该服务的任务数据 |
| S3 | **语音输出 TTS + 语种/音色分离** | 六套 edge-tts 音色：大陆中文 `zh-CN-YunxiNeural`、台灣中文 `zh-TW-HsiaoChenNeural`、美式 `en-US-BrianMultilingualNeural`、英式 `en-GB-RyanNeural`、加拿大 `en-CA-LiamNeural`、香港 `en-HK-SamNeural`；回复语种七档、朗读音色八档（默认跟随语种），另有离线 SAPI | 回复完整后整段合成一次；可开关；语种和音色可分开切换；选英文语种后用英文回答；跨语言组合有提示但可保存 |
| S4 | **语音输入 ASR**（可选） | 点击“🎤 语音输入”开始，再点“停止录音”；Vosk 离线识别 → 文字填入输入框，不自动发送 | 常见短句可用；缺模型/麦克风时给提示，不影响文字流程 |
| S5 | **健康陪伴模块（保留）** | 沿用 V1：健康记录、医疗知识库 RAG、健康趋势、就医提示 | 说不适→记录→检索→建议，闭环可复现 |
| S6 | **微信代发提醒（人工审查）** | 到点生成内容 → 打开微信 → 粘贴 → 用户手动发送 | 绝不自动发送；粘贴内容可编辑 |

|---|---|---|---|

### 3.4 明确不做（Won't，本期）

| 不做 | 原因 |
|---|---|
| 医疗诊断、开药、替代医生 | 法律与伦理边界，只做科普与就医提示 |

| 云同步 | 涉及隐私与服务器成本，先用本地 SQLite |
| 自动发送微信消息 | 发错人/发错内容不可挽回，必须人工审查 |
| 复杂图表仪表盘 | 简约窗口即可，不做数据分析大屏 |
| 依赖向量数据库 | 规模不需要，见 `MEMORY_DESIGN.md` §7 |

## 4. 系统架构

```
┌──────────────────────────────────────────────────────────┐
│                    桌面层（PyQt6）                        │
│   三线任务看板  │  任务编辑  │  提醒设置  │  对话区  │ 托盘  │
└───────────────────────────┬──────────────────────────────┘
                            │ 直接函数调用（同进程）
┌───────────────────────────▼──────────────────────────────┐
│                   编排层（agent core）                     │
│  意图判定 → 上下文组装 → 模型调用 → 工具循环 → 结果回报      │
└──────┬─────────────┬──────────────┬──────────────┬────────┘
       │             │              │              │
┌──────▼─────┐ ┌─────▼──────┐ ┌─────▼─────┐ ┌──────▼──────┐
│ 记忆层      │ │ 任务层      │ │ 调度层     │ │ 工具层       │
│ L1/L2/L3    │ │ tasks      │ │ APScheduler│ │ 内置工具      │
│ 检索+组装    │ │ reminders  │ │ 补发错过    │ │ MCP 客户端    │
│ SQLite      │ │task_events │ │ 触发提醒    │ │ HTTP 工具     │
└────────────┘ └────────────┘ └───────────┘ └──────────────┘
                            │
                    ┌───────▼────────┐
                    │ 外部能力（可选） │
                    │ 自建 FastAPI   │
                    │ MCP 服务器      │
                    │ 智谱 / edge-tts │
                    └────────────────┘
```

### 4.1 模块边界

| 模块 | 只负责 | 不负责 |
|---|---|---|
| desktop | 展示与用户输入 | 不写业务逻辑、不直接碰数据库 |
| agent core | 意图判定、上下文组装、工具循环 | 不直接操作 UI |
| memory | 存储与检索记忆 | 不决定"该不该注入"（由 core 决定） |
| tasks | 任务 CRUD 与进度轨迹 | 不负责提醒触发 |
| scheduler | 按规则触发、补发错过 | 不负责任务状态变更 |
| tools | 工具定义与执行、MCP 接入 | 不负责结果呈现 |

### 4.2 关键数据流（典型链路）

```
"帮我排一下这周软考复习"
  → desktop 把文本交给 core
  → core 意图判定：任务编排
  → core 取 L3 事实（考试日期）+ 今日状态 + 相关记忆
  → 调模型 → 模型返回"需要建 5 个子任务"（function calling）
  → tools 执行 task_create × 5
  → 任务层写入 tasks / task_events
  → 调度层为每个截止时间生成 reminder
  → 结果回灌模型 → core 生成自然语言汇报
  → desktop 刷新看板 + 显示回复
```

### 4.3 接口风格

本项目**无 HTTP 层**（桌面单进程），模块间使用 Python 函数接口，统一约定：

| 约定 | 说明 |
|---|---|
| 返回值 | 一律返回 dict / list，不用裸 bool |
| 错误 | 抛自定义异常，由 core 统一捕获并转成用户可读提示 |
| 副作用 | 写操作必须返回"是否成功 + 影响行数/新建 id" |
| 幂等 | 建提醒/建任务支持按外部 key 去重，避免工具重试导致重复数据 |

> 何时引入 HTTP：C3 手机版、多人使用、对外提供 Demo 访问（记为 ADR-002，见下）。

### ADR-002：本期不引入 HTTP（FastAPI）

| 项 | 内容 |
|---|---|
| 决策 | 桌面单进程直接函数调用，不部署 HTTP 服务 |
| 理由 | UI 与业务同进程，无远程客户端；引入 HTTP 只增多一个进程与调试环节，收益为零 |
| 影响 | 手机版/远程访问需先补 HTTP 层，但业务逻辑层不受影响（已按分层设计） |
| 复用点 | 自建的 FastAPI 项目通过"HTTP 工具"或"MCP 服务"接入，而非改造本项目 |

## 5. 技术栈

| 模块 | 技术 | 用途 | 备注 |
|---|---|---|---|
| 主模型 | 智谱 GLM-4.7-Flash | 对话、工具调用 | 免费档；版本与额度以官方文档为准 |
| 向量模型 | 智谱 embedding-3 | 记忆与知识库向量化 | 随账号免费 |
| GUI | PyQt6 | 简约窗口、托盘、弹窗 | 已装 6.11 |
| 存储 | SQLite（WAL 模式） | 记忆、任务、提醒 | 零配置、单文件 |
| 调度 | APScheduler | 定时触发、cron、补发 | 新增，需持久化 jobstore |
| 语音 | edge-tts（大陆中文 `zh-CN-YunxiNeural`；台灣中文 `zh-TW-HsiaoChenNeural`；美式 `en-US-BrianMultilingualNeural`；英式 `en-GB-RyanNeural`；加拿大 `en-CA-LiamNeural`；香港 `en-HK-SamNeural`；默认 `+0% / +0Hz`） | TTS + 回复语种 + 朗读音色 | 联网调用公开接口，个人非商用；语种与音色分别设置，默认音色跟随语种 |
| MCP | Python MCP SDK（stdio / HTTP-SSE） | 外部工具接入 | 包名与传输方式实现前核对官方文档 |
| 日志 | logging + TimedRotatingFileHandler | 终端+文件双写 | 沿用 V1 |
| 测试 | pytest | 单元 + 功能验证 | 已装 |

### 5.1 MCP 的两条路径（重要取舍）

| 路径 | 做法 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| **A. 直连 HTTP** | 把自建 FastAPI 的接口封装成 function calling 工具 | 简单、延迟低、调试直观 | 只能被本项目用 | **先做**（S2） |
| **B. 封装 MCP 服务** | FastAPI 外层包一层 MCP server（stdio 或 HTTP-SSE） | 标准化、可被其他客户端复用；面试可讲协议理解 | 多一层协议与进程管理，排错成本高 | S1 做，演示扩展性 |

> 结论：先用 A 打通业务，再用 B 演示架构扩展性。不要为了"用 MCP"给单机项目套两层协议。
>
> **2026-11-26 实现状态**：B 的 **stdio 客户端**已落地（`core/mcp_client.py`，自研 JSON-RPC 2.0，未使用第三方 MCP SDK）；HTTP/SSE 传输与 S2 仍未做。

## 6. 成功指标

### 6.1 北极星指标

**每周有效任务闭环数**——被创建且最终标记为 done 的任务数量（衡量"管理"是否真的发生）。

### 6.2 次级指标

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 提醒准时率 | ≥ 99% | 触发时间与实际计划时间差值统计 |
| 错过补发率 | 100% | 关机期间错过的提醒在启动后补发数 / 错过总数 |
| 任务创建→完成转化 | ≥ 60% | 周内 done 任务 / 新建任务 |
| 对话工具命中率 | ≥ 90% | 需要工具时实际触发工具的比例 |
| 首 token 延迟 | < 2s | 客户端打点 |
| 记忆关键事实召回率 | ≥ 90% | 抽 10 条事实反向提问 |
| 崩溃次数 | 0 / 周 | 错误日志统计 |

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 免费模型工具调用不稳定 | 该建的任务没建 | 提示词写死顺序 + 关键操作代码侧校验（提醒必须有时间） |
| MCP 生态与包版本变动快 | 接入失败 | 先走 HTTP 路径，MCP 作为可选项；锁版本并记录 |
| APScheduler 与 GUI 线程冲突 | 提醒不触发或界面卡死 | 调度器独立线程 + 触发后通过 Qt 信号切回主线程 |
| 关机错过提醒 | 用户以为没提醒 | `next_fire_at` 持久化 + 启动补发 + `missed_count` 留痕 |
| 记忆污染导致排期错乱 | 计划基于错误事实 | 先蒸馏后摘要 + confidence 分级 + 人工删除入口 |
| edge-tts 依赖第三方接口 | 语音失效 | 语音可关闭，主流程不依赖 TTS |
