## 三、本轮我们完成了什么（大白话版）

### 1. 从“跑个冒烟”升级成三层测试

以前只有“能不能启动、能不能聊一句”的冒烟脚本；这轮补了三层，出了问题能定位到具体模块：

- **离线功能审计**：不连模型、不花钱，50 项检查把数据库、任务、提醒、工具、上下文、调度全部过一遍。
- **真实模型评测**：18 个任务场景、11 轮连续对话，真调 `glm-4-flash`，检查“说的事有没有真的写进库”。
- **记忆专项评测**：24 条带时间的语料 + 8 条噪声 + 10 个换说法问句，量 R@1、R@3、MRR 和噪声。

这些脚本都可重复跑，全部使用独立测试库，不碰正式数据：

```powershell
python scripts\functional_audit.py   # 50 项离线检查
python scripts\memory_eval.py        # 记忆检索评测（会调 embedding）
python scripts\task_eval.py          # 任务场景评测（会调模型）
python scripts\chat_flow.py          # 11 轮连续对话
```

### 2. 修掉 23 个真问题，重点是“假办好”

最严重的一类不是报错，而是**嘴上说办好了、库里什么都没有**。例如多轮聊天里说“明天下午两点提醒我”，Andy 回“已设置”，但提醒表是空的。

现在加了三道保险：

1. 动作意图明确时，首轮就锁定对应工具；
2. 回复声称“已设置/已记下/已标记”，但本轮没有任何成功写操作 → **丢掉多轮历史，只带当前这句话重试**；
3. 重试仍不调工具 → 如实说“没写进系统，请再说一次”，不再骗用户。

另外修了：截止时间解析失败却静默丢、同一任务重复建、拆解子步骤继承父截止导致“今日到期”虚增、长期记忆工具字段名写错永远存不进去、问句被反写成事实、提醒只给日期不追问钟点、错过 2 小时却记 0 次、界面未完成计数把已完成算进去、提醒开关空选崩溃等。完整清单（现象/根因/修法/验证）在 `docs/TEST_REPORT.md`。

### 3. 记忆机制：从“能搜”到“搜得准、搜得干净”

用通俗的话说，改了三件事：

- **只记该记的**：用户原话才参与召回，Andy 自己的复述不再抢排名；“我对花生过敏”能正确抽出“花生”，问“我是不是过敏”不会再写一条假事实。
- **该中的排前面**：排序从“按名次融合”改成“语义分为主，名次和时间只做小幅修正”；再加主题加权——问健康就优先健康那条，问吃饭就优先过敏那条。问“今天状态”不会再被“今天天气不错”压住。
- **不该中的别进来**：加了语义门槛和近义去重，top3 里无关内容的平均条数从 0.7 降到 0.1。

同时修了小语料冷启动（只有 3 条记忆时也能召回）、最近高分误杀老记忆、称呼被 12 条偏好挤掉等问题。

### 4. 任务完成更准、更省事

- 拆任务最多 6 步，子步骤不再继承父任务的截止时间，不会把“今日到期”算多。
- 建任务重复会识别出来，不再一问两遍出现两条。
- 截止时间看不懂会明确让用户补，不假装记好。
- 只说“明天提醒我”会追问几点，不让模型自己编 09:00。
- 说“做到一半”只报进度时，任务会自动从“待办”转“进行中”，不再出现“进度 50% 还是待办”。
- 同一轮里重复调同一个工具会跳过，避免重复写库。
- 用“那个答辩的活儿”这类别名找任务，匹配到多条会反问编号，不会闷头改错一条。

### 5. 界面小修

- “未完成 N 项”不再把已完成算进去。
- 提醒页没选中就点开关，给提示而不是崩溃。
- 补发提醒文案不再出现“补发：启动时补发提醒”这种重复前缀。

### 7. MCP 客户端框架

以前接一个外部能力就要改 `core/tools.py` 再重启；现在加服务只改配置：

- `core/mcp_client.py`：自己实现 stdio JSON-RPC 2.0，不依赖第三方 `mcp` 包；负责启动子进程、`initialize` 握手、`tools/list` 分页发现、`tools/call` 调用、超时和 stderr 留存。
- `MCPManager`：读 `mcp_servers.json`，把每个工具改成 `mcp__<server>__<tool>`，转成 OpenAI function schema，和内置工具合并；单个 server 失败只记录、不影响其他。
- 权限门：只读工具（`readOnlyHint=true`）直接放行；写入工具要 `MCP_ALLOW_WRITE=1` + server 配置 `allow_write=true` + 每次确认，缺一项就拒绝。
- `scripts/mcp_demo_server.py`：只用标准库的 demo，提供 `echo` / `now` / `write_note`，用来验证链路。
- 主入口启动时拉起所有 server，退出时关闭；窗口里写入确认通过信号切回主线程弹框，避免后台线程直接开 Qt 对话框。

真实集成验证：demo 1 个 server、3 个工具；`tools.get_tools()` 暴露内置 8 + MCP 3；`call_tool("mcp__demo__echo")` 返回 `echo: 路由成功`；`write_note` 确认后写入成功。

### 8. 语音播报与语种/音色分离

- `core/voice.py`：先清洗文本（去代码块、链接、Markdown 符号、emoji，超 240 字按句截断），再合成播放。
- 合成优先 edge-tts。回复语种和朗读音色拆成两套设置：`language_mode` 管回复语言（`auto/zh-CN/zh-TW/en-US/en-GB/en-CA/en-HK`），`voice_mode` 管嗓子（`follow/zh-CN/zh-TW/en-US/en-GB/en-CA/en-HK/sapi`）。默认音色 `follow` 跟随语种；手动选到跨语言组合时界面提示“可能不自然”，但不阻止保存。失败退回 Windows SAPI（按文本语言选系统声音），两者都失败只显示文字。
- 语种不只是换音色：`prompts.LANGUAGE_INSTRUCTIONS` 给模型硬性回复语言约束，并在首条 system、用户句前 system、中文提问句尾各压一次，避免历史中文把回复带回去。
- 独立 daemon 线程 + 12 条队列，新消息打断上一段；pygame 播放，可被 `stop()` 中断；启动预热音频设备。
- 整段播报：回复完成后对完整 `reply` 合成一次，不再边流式边按句起播；`core/voice.py` 的 `_play_edge` 只生成一个音频文件，减少断续和重复起播。
- 窗口输入框旁加“朗读”复选框和“语言/音色”按钮（两个下拉框），两项分别写 `QSettings` 的 `language_mode` 与 `voice_mode`，旧单档设置自动迁移；CLI 用 `--voice --lang`，可再加 `--voice-mode` 单独指定音色；默认关闭，不主动打扰。
- 真实链路：6 个音色均合成成功，总耗时 13.52 秒；真实模型切到 `en-GB/en-HK/en-US/en-CA` 均英文回复，`zh-TW` 繁體中文回复；解绑后 `en-GB` 语种 + `zh-CN` 音色仍保持英文回复、中文嗓子，两项互不覆盖。

### 8.1 语音输入（ASR）

- `core/asr.py`：Vosk 离线模型 + `sounddevice` 采集 16kHz / 单声道 / 16bit PCM；模型懒加载，缺模型/缺依赖/没麦克风时抛 `AsrError`，界面给可操作提示。
- 桌面 `ASRWorker` 子线程录音识别，`partial` 信号实时回填临时结果，`done` 信号把最终文本填入输入框；不自动发送，用户可改字后回车。
- 输入框旁“🎤 语音输入”按钮：点一下开始，再点一下停止；模型准备阶段显示“准备中…”，录音阶段显示“停止录音”。
- 识别结果做中文空格归一化；长句按 Vosk 的停顿结果用逗号连接，避免“你 好 世 界”这种空格文本直接进模型。
- 真实模型：官方 `vosk-model-small-cn-0.22.zip` 完整下载 43,898,754 字节并解压；把中文 TTS 样本转成 16kHz 单声道 WAV 后识别，输出“你好我是安迪”。`sounddevice` 已识别本机 `麦克风阵列 (Realtek(R) Audio)`，16kHz/单声道/int16 参数校验通过；真人麦克风端到端复测还没做。
